# Poneglyph — build contract (read fully before writing any file)

Frontend-only **sandbox** of an agentic SEBI-compliance engine, demo tenant = *Walrus Securitas Broking Ltd* (simulated stock broker). Everything explorable (click/expand/open), **nothing actionable** — action buttons fire the sandbox toast. Next.js 16 App Router + TypeScript, **no Tailwind, no new deps**. All data is static TS in `data/`, typed by `lib/schema.ts`.

## Brand rules (non-negotiable — this is the Walrus LinkedIn-post design system)

- **Tokens/classes come from `app/globals.css`. Never hardcode colors** — use `var(--ink)`, `var(--orange)`, `var(--ink-40)`, etc. White theme only.
- **Orange strictly means "needs attention"** (gaps, overdue, live/pulse accents) — plus tiny brand accents (eyebrow dash, plus-marks). Never decorate large surfaces orange.
- Type: serif-light display headlines (`.display`, optional `<span className="accent grad">` for 1–3 emphasized words), body sans, ALL labels/ids/timestamps in `.mono-label` / `.mono-value`. Legal text uses `.clause-text`.
- Compose from `components/ui.tsx`: `MarkedCard, PageHead, Eyebrow, StatusChip, TaskChip, Chip, StatTile, Cta, Hairline, KV` + `components/DashField.tsx` (decorative, sparingly, `opacity≤0.5`). Tables: `<table className="table">`. Terminal: `.terminal` classes. Diff: `.diff-add/.diff-del/.diff-unchanged`. Expandables: `<details>` or client state.
- Every page starts with `<PageHead eyebrow="…" title={…} sub="…" />`. Title = serif sentence with one `accent grad` phrase (see `app/page.tsx` exemplar). Density: generous whitespace, hairlines between sections, `.grid cols-N` for layout.
- **Hydration safety:** never call `Math.random()`/`Date.now()`/`new Date()` during render. All dates come from data (`tenant.simToday` = "2026-07-12"). Animations: CSS or `useEffect` timers in client components.

## Component/API notes

- Pages may be server components; anything with hooks/state → `"use client"` file.
- `useSandboxToast()` from `components/toast` for disabled actions; `Cta` already does this by default.
- `usePersona()` from `components/persona` → `"broker" | "inspector"`. Hide approve/reject-style broker controls when inspector.
- Imports use `@/` alias. Icons: none installed — use typographic marks (→ ✓ ✕ ◆ ▸) sparingly.
- App shell (`components/AppShell.tsx`): left sidebar with grouped nav (Oversight / Compliance / Engine, from `lib/nav.ts`), tenant card, bottom profile block whose dropdown holds the Broker ↔ Inspector switch; content column has a sticky header with breadcrumbs (`group / label`) + route-slug chip. Pages render inside `main.shell` unchanged. Breadcrumbs are links (group → first page of its group, label → current route); the slug chip is a button that copies the pathname and toasts.
- Register deep-link contract: `/register?chapter=&status=&type=&id=` — `RegisterTable` initializes its filters from the URL, keeps the URL in sync on every filter change (`router.replace`, no scroll), and `?id=` expands that row and scrolls it into view. Invalid values degrade to `all`. Anything that points at the register (dashboard heat-map cells, legend chips, pending-review chips) should link with these params. `RegisterTable` reads `useSearchParams`, so it must stay wrapped in `<Suspense>` in `app/register/page.tsx` or the static build fails.
- Page titles are literal — `Function <span class="accent grad">Noun</span>` (e.g. "Obligation Register", "Evidence Vault"). Personality lives in the `sub` line, not the title.

## Page specs (owners; each page agent writes ONLY its `app/<route>/` files)

Shared shape: `PageHead` → stat/summary strip → main content → cross-links to related tabs (`<Link href="/register">` etc). Read `app/page.tsx` first as the exemplar.

- `/watchtower` — animated terminal replay of scraper run (client: lines appear on a `useEffect` interval, replay button; content from RUN-048 + static "watching" header with next-poll ETA), then catches list (newest first): marked-cards with docType chip, fetchedAt, applicability verdict chip (applies=gap-tone attention / partial=at-risk / not-applicable=info) + expandable cited reasoning (clause-text blockquote) + "→ triggered RUN-047" link to /agents.
- `/register` — filter chips (chapter, status, type) + table of all 33 obligations: id, title, chapter, type/frequency, owner, deadline, StatusChip. Row click expands (client): summary, clause excerpt in `.clause-text` with `.clause-hl`, KV rows (control, evidence spec, bound evidence ids → link /evidence, createdByRun → link /agents, hash), and for `pending-review` a broker-only approve/reject Cta pair (toast). "View clause" opens an in-page drawer/modal rendering the full chapter paras from corpus with the cited para highlighted.
- `/amendments` — hero: timeline strip (MC-2024 → MC-SB-2025 → CIRC-CUSPA-2026); then side-by-side redline of `cuspaAmendment.changes` (old `.diff-del`, new `.diff-add`, unchanged dimmed), each block expandable showing delta obligations (StatusChip + link to /register) ; footer: phased-deadline banner (guidelines ~Aug 2 → phase-1 ~Nov 2 → phase-2 Jan 3 2027) + "10 obligations re-mapped, 23 untouched" stat.
- `/evidence` — stat strip (by kind), filterable card grid of all 20 artifacts: kind chip (document ◆ / data-check ▸ / live-scan with pulse dot), title, connector mono-label, capturedAt, hash, bound obligations links; expand → detail (docExcerpt / checkQuery+checkResult / scanTool+scanFindings) + history timeline. Empty-evidence callout: "6 obligations have no bound evidence → /remediation".
- `/remediation` — list/kanban toggle (client) of 9 tasks: TaskChip, priority, owner avatarinitials, due (overdue→orange), obligation chain "TSK-002 ← OBL-SB-102 ← clause 46.2" with links; detail expand with description + createdByRun.
- `/agents` — runs table (id, trigger, startedAt, duration, status, outputs counts); click run → replayable trace (client, step-through or all-at-once): TraceSteps as timeline with agent badges, thought/action/observation in mono; verifier checks as ✓ list; RUN-047 featured on top as a marked-card "latest pipeline". Include the architecture placard: deterministic pipeline / ephemeral agents / schema permanent / human gate (small diagram from styled divs).
- `/audit` — hash-chain visual: vertical chain of events, each card `hash` + `prevHash` linked by a line; filter by subjectType/subjectId (client); "Verify chain" Cta runs an animated pass (client: sequential ✓ down the chain, ends "chain intact — 40 events, 0 breaks"); subject links to /register//evidence.
- `/mcp` — endpoint marked-card (`https://mcp.poneglyph.walrussecuritas.com/v1 · SSE` + copy button→toast), tool cards with inputSchema in `.terminal` block, config snippets (Claude Desktop JSON / Claude Code command) in terminal blocks, playground: scripted chat replay (client, from `playgroundScript`, animated), and "Share with SEBI" card: inspector-scoped read-only token generator (Cta → toast) + blurb.
- `/inspector` — inspector landing (persona auto-switches here): "Inspection session — Walrus Securitas Broking Ltd" header, posture summary tiles, "start the walk-back" cards linking Register/Evidence/Audit/MCP, and the ecosystem teaser: "12 intermediaries publish this ontology — comparable compliance, zero divergent interpretations" (DashField decoration). Read-only: no broker actions anywhere.
