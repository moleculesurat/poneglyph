# Poneglyph — build contract (read fully before writing any file)

Frontend-only **sandbox** of an agentic SEBI-compliance engine. Demo tenant = **Angel One Limited**, a real listed SEBI-registered stock broker. Everything explorable (click / expand / filter / replay / deep-link), **nothing actionable** — action buttons fire the sandbox toast. Next.js 16.2.10 App Router + React 19 + TypeScript, **no Tailwind, no new deps**. All data is static TS in `data/`, typed by `lib/schema.ts`; the SEBI taxonomy is in `lib/domains.ts`.

Poneglyph is a standalone product. There is **no parent company, no vendor, no "by X"** anywhere in copy, chrome or asset names.

## Real vs simulated (governs every line of copy you write)

| Class | What it covers | How it must be rendered |
|---|---|---|
| **Real** | Angel One's identity, ISIN INE732I01021, NSE ANGELONE / BSE 543235, net worth ₹6,201.98 cr and revenue ₹5,054.07 cr (FY2025-26 standalone XBRL), net profit ₹1,215.95 cr (FY2024-25), client base 38.59 mn (Jun 2026 update), NSE share 14.79% | State it, and name the source. Sources live on `EntityFact.source`; never retype a figure that `data/entity.ts` already carries |
| **Derived** | ≈6.76 mn NSE active clients, net-worth movement | Label `derived`, `verified: false`, show the arithmetic |
| **Declared** | Registration **INZ000161534** (public but unverified), exchange memberships, CDSL participation | Chip it `declared`. Never invent a registration number — every other number in `registrations` is masked |
| **Simulated** | **All compliance posture**: obligations met/gapped, evidence, tasks, audit events, document contents, onboarding narrative, all traces | Label it illustrative on the page. Never assert or imply that Angel One is non-compliant. No finding, violation, inspection outcome or penalty may be depicted |

QSB and the CSCRF grade are **computed by the engine and flagged COMPUTED · UNCONFIRMED** — never presented as read off a published list. What the engine cannot verify it reports as unverified, never as compliant.

## Brand rules (non-negotiable — the Poneglyph design system)

- **Tokens/classes come from `app/globals.css`. Never hardcode colors** — use `var(--ink)`, `var(--orange)`, `var(--orange-deep)`, `var(--ink-10)`, `var(--ink-40)`, etc. White theme only.
- **Orange strictly means "needs attention"** (gaps, overdue, open asks, live/pulse accents) — plus tiny brand accents (eyebrow dash, plus-marks). Never decorate large surfaces orange.
- Type: serif-light display headlines (`.display`, optional `<span className="accent grad">` for 1–3 emphasized words), body sans, ALL labels/ids/timestamps in `.mono-label` / `.mono-value`. Legal text uses `.clause-text`.
- Compose from `components/ui.tsx`: `MarkedCard, PageHead, Eyebrow, StatusChip, TaskChip, Chip, StatTile, Cta, Hairline, KV` + `components/DashField.tsx` (decorative, sparingly, `opacity ≤ 0.5`). Tables: `<table className="table">` inside an `overflowX: auto` wrapper. Terminal: `.terminal` classes. Diff: `.diff-add/.diff-del/.diff-unchanged`. Expandables: `<details>` or client state.
- `Chip` tones: `met | gap | at-risk | pending | info | live`. `StatTile` takes `label, value, accent?, hint?`. `Cta` takes `variant?: "orange" | "ghost"` and `toastMsg?`.
- Every page starts with `<PageHead eyebrow="…" title={…} sub="…" right={…} />`. Title = literal `Function <span class="accent grad">Noun</span>` ("Obligation Register", "Document Vault"); personality lives in `sub`, not the title. See `app/page.tsx` as the exemplar. Density: generous whitespace, hairlines between sections, `.grid cols-N` for layout.
- **No emoji in UI chrome.** No lorem ipsum — all copy in-world, precise, regulator-grade sober.
- **Hydration safety:** never call `Math.random()`/`Date.now()`/`new Date()` during render. All dates come from data (`tenant.simToday = "2026-07-12"`); date comparisons are ISO string compares. Animations: CSS or `useEffect` timers in client components.

## Component/API notes

- Pages may be server components; anything with hooks/state → `"use client"` on line 1. Shared derivations that both halves need go in a plain module (see `app/documents/shared.ts`).
- `useSandboxToast()` from `components/toast` for disabled actions; `Cta` already does this by default.
- `usePersona()` from `components/persona` → `"broker" | "inspector"`. Hide approve/reject-style broker controls when inspector.
- Imports use the `@/` alias. Icons: none installed — use typographic marks (→ ✓ ✕ ◆ ▸) sparingly.
- App shell (`components/AppShell.tsx`): left sidebar with grouped nav (Oversight / Compliance / Engine / Inspection, from `lib/nav.ts`), tenant card, bottom profile block whose dropdown holds the Broker ↔ Inspector switch; content column has a sticky header with breadcrumbs (`group / label`) + route-slug chip. Pages render inside `main.shell` unchanged. Breadcrumbs are links (group → first page of its group, label → current route); the slug chip is a button that copies the pathname and toasts.
- **Register deep-link contract:** `/register?part=&chapter=&status=&type=&id=` — `RegisterTable` initializes filters from the URL, keeps the URL in sync on every filter change (`router.replace`, no scroll), and `?id=` expands that row and scrolls it into view. `?part=` and `?chapter=` interact: a chapter outside the selected Part degrades to `all`. Invalid values degrade to `all`. Anything pointing at the register (dashboard heat-map cells, legend chips, onboarding Part cards, document "unlocks" links) links with these params.
- **Document deep-link contract:** `/documents?part=&category=&status=&req=` — same discipline; `?req=` expands that requirement and scrolls it into view.
- Both explorers read `useSearchParams`, so each must stay wrapped in `<Suspense>` in its `page.tsx` or the static build fails.
- **Part is derived, never stored.** `Obligation.clause.chapter` is the stored dimension; the SEBI Part comes from `partOf(chapter)` in `lib/domains.ts`. Never redeclare a chapter → Part map or a chapter label anywhere else.

## Taxonomy contract — `lib/domains.ts`

Single source of truth for the SEBI taxonomy. Sourced from the **Master Circular for Stock Brokers, ref SEBI/HO/MIRSD/MIRSD-PoD-1/P/CIR/2024/53**; Part titles are verbatim from its Table of Contents.

- `SEBI_DOMAINS: SebiDomain[]` — Parts **I–X** in circular order, each `{ part, title, blurb, chapters, items }`.
- `CHAPTER_PART: Record<ChapterKey, SebiPart>` and `CHAPTER_LABEL: Record<ChapterKey, string>` — `ChapterKey` is **15 keys** (`registration, supervision, client-dealings, margin, unpaid-securities, technology, cyber, change-control, fatca, grievance, default, advertisement, books-records, outsourcing, reporting`), widened from the original 9 so every Part is reachable.
- Lookups: `domainOf(chapter)`, `partOf(chapter)`, `domainByPart(part)`, `partLabel(part)` → `"Part III · Dealings with Client"`.
- Overlay frameworks: `CSCRF` (name, circular `SEBI/HO/ITD-1/ITD_CSC_EXT/P/CIR/2024/113`, issuedOn, note, 5 grades), `CSCRF_GRADE_LABEL: Record<CscrfGrade, string>`, `QSB` (name, circular `SEBI/HO/MIRSD/MIRSD-PoD-1/P/CIR/2023/26`, effectiveFrom, note, 7 designation `parameters`).

## Page specs

Shared shape: `PageHead` → stat/summary strip → main content → cross-links to related tabs (`<Link href="/register">` etc). Read `app/dashboard/page.tsx` first as the exemplar. Thirteen routes: the full-bleed entry gate at `/` (`app/page.tsx`), the eleven in `NAV_ITEMS` (broker home is `/dashboard`), plus `/inspector` (`INSPECTOR_HOME`).

- `/dashboard` **Dashboard** (`BROKER_HOME`) — CUSPA amendment alert card; tenant line stating real-entity / simulated-posture with `factOf()` facts; posture stat tiles; `DeadlineRunway`; Part I–X → chapter heat-map whose cells deep-link with `/register?part=&chapter=&id=`, plus status-legend chips linking `/register?status=`; latest catches and runs.
- `/onboarding` **Entity Onboarding** — the entity axis. Session strip (ONB-001, mode, signed by the Compliance Officer). A real/illustrative card **before anything is claimed**. Entity card: legal name, listed/ISIN/ticker chips, capacities, exchanges, depositories, segment chips, ruled-out segments, the 7-line registrations table (declared vs masked), 4 headline stat tiles each naming its filing, and a `<details>` table of all 18 facts with provenance chips. `FlowTimeline` renders the 6 steps with replayable traces; the `designation` step takes an injected extra rendering the **QSB scoring table** (parameter · value · crosses? · source — one CROSSES, six NOT COMPUTABLE), the determination panel, and the CSCRF grade panel. Scope section walks all ten Parts as `MarkedCard`s — applicable vs `excluded · dormant`, what each binds on (parsed from the scope agent's own trace), chapter chips linking to `/register?chapter=`, Part VIII's determination in full behind a `<details>`. `QuestionDeck` renders 12 questions (pre-filled vs asked cold, each with its `why`); the free-text catch-all gets its own card last. Document handoff strip → `/documents`. `NewOnboarding` closes the page with the blank six-step template (Cta → toast).
- `/documents` **Document Vault** — distinct from Evidence, and the page says so in a two-column card: *evidence = proof a control ran; documents = the source material the engine learns the firm from*. Five status stat tiles (Verified / Received / **Required** accent / Expired / Waived). "Open asks" section: the 6 requirements with nothing supplied, each panel orange-left-bordered with `triggeredBy`, `unlocks` → register links, accepted formats, cadence. "What the engine did not ask for": the filed non-asks with their waiver reasons, plus the Part VIII note. The full requirement matrix (`DocumentExplorer`, `<Suspense>`-wrapped) faceted by Part / category / status with `?req=` expansion. Parsing posture: fields extracted, extractions below the 0.75 review threshold shown flagged rather than smoothed, documents answered at onboarding. "Volunteer a document" card. Provenance card naming DOC-015 as the one real extraction set.
- `/watchtower` — animated terminal replay of the scraper poll (client: lines on a `useEffect` interval, replay button; from RUN-048 + a "watching" header with next-poll ETA), then catches newest-first: marked-cards with docType chip, `fetchedAt`, applicability verdict chip (applies = gap tone / partial = at-risk / not-applicable = info), expandable cited reasoning in a `.clause-text` blockquote, and "→ triggered RUN-047" linking to `/agents`.
- `/register` — filter chips (Part, chapter, status, type) + table of all 43 obligations: id, title, chapter/Part, type/frequency, owner, deadline, `StatusChip`. Row click expands (client): summary, clause excerpt in `.clause-text` with highlight, KV rows (control, evidence spec, bound evidence ids → `/evidence`, `createdByRun` → `/agents`, hash), and for `pending-review` a broker-only approve/reject `Cta` pair (toast). "View clause" opens the `ClauseDrawer` rendering the full chapter paras from the corpus with the cited para highlighted.
- `/amendments` — phased-deadline milestone strip positioned on a fixed 2026-06-26 → 2027-01-26 axis: amendment issued 2026-07-03 → exchange operational guidelines due 2026-08-02 → phase 1 in force 2026-11-02 (paras 46.1–46.11) → phase 2 in force 2027-01-03 (paras 46.12–46.14). Then the side-by-side `Redline` of `cuspaAmendment.changes` (old `.diff-del`, new `.diff-add`, unchanged dimmed), each block expandable to its delta obligations (`StatusChip` + link to `/register?id=`); footer stat: "10 obligations re-mapped, 33 untouched" — derived from the data, not typed.
- `/evidence` — stat strip by kind, filterable card grid of all 24 artifacts: kind chip (document ◆ / data-check ▸ / live-scan with pulse dot), title, connector `.mono-label`, `capturedAt`, hash, bound obligation links; expand → detail (`docExcerpt` / `checkQuery`+`checkResult` / `scanTool`+`scanFindings`) + history timeline. Empty-evidence callout counts the obligations with an empty `evidenceIds` and routes to `/remediation` — derive the number, never type it.
- `/remediation` — list/kanban toggle (client) of the 11 tasks: `TaskChip`, priority, owner initials, due (overdue → orange), obligation chain "TSK-002 ← OBL-SB-102 ← clause 46.2" with links; detail expand with description + `createdByRun`.
- `/agents` — runs table (id, trigger, startedAt, duration, status, output counts); click a run → replayable trace (client, step-through or all-at-once): `TraceStep`s as a timeline with agent badges, thought/action/observation in mono; verifier checks as a ✓ list; RUN-047 featured on top as the latest-pipeline marked-card. Include the architecture placard (styled divs, no images): deterministic pipeline / ephemeral agents / permanent schema / human gate.
- `/audit` — hash-chain visual: vertical chain of events, each card's `hash` + `prevHash` joined by a line; filter by subjectType/subjectId (client); "Verify chain" `Cta` runs an animated pass (sequential ✓ down the chain, ends "chain intact — 56 events, 0 breaks" (the count is derived from `auditEvents.length`)); subjects link to `/register` and `/evidence`.
- `/mcp` — endpoint marked-card (**`https://mcp.poneglyph.dev/v1` · SSE**, `CopyChip` → toast), the 7 tool cards with `inputSchema` in `.terminal` blocks and example call/result behind `<details>`, config snippets (Claude Desktop JSON keyed `poneglyph` / `claude mcp add --transport sse poneglyph`) in terminal blocks, `Playground` scripted chat replay (client, from `playgroundScript`), and a "Share with SEBI" card: inspector-scoped read-only token generator (Cta → toast) + blurb.
- `/inspector` — inspector landing; `InspectorMode` auto-switches the persona on mount. Header eyebrow `Inspection session · ${tenant.name}`, posture summary tiles, and the four-stop `WALK_BACK` (01 `/register` → 02 `/evidence` → 03 `/audit` → 04 `/mcp`), each stop stating what the inspector can independently verify there. Closes on the ecosystem teaser: "12 intermediaries publish this ontology — comparable compliance, zero divergent interpretations" (DashField decoration). Read-only: no broker actions anywhere.
