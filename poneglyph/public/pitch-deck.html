Problem — in SEBI's own framing

Regulation is text for humans. Compliance systems need machine-checkable rules.

Pain 1 · Interpretation

When SEBI issues or amends a circular, a human reads the PDF, decides whether it binds their firm, maps it to internal processes, and updates them. The work is slow, manual, and divergent — two firms read the same clause differently, and the regulator inherits the inconsistency.

Pain 2 · Proof

Compliance teams must track every standing obligation, hold evidence that each is fulfilled, and produce audit trails on inspection. Smaller intermediaries carry the same rulebook with the least capacity — the firms with the thinnest compliance teams hold the most gaps.

The bridging problem — unstructured regulatory text → structured, auditable, operational compliance — is what PS2 names as the core unsolved problem. The suggested corpus, the Master Circular for Stock Brokers, is the corpus this prototype runs on.

System overview — a fixed pipeline, not a free agent

A new regulation is a new job through a fixed pipeline.

watch → applicability → extract → verify (deterministic) → human gate → evidence → gap → task → diff on amendment → hash-chained audit
Watch / decideA scraper polls SEBI daily; an applicability agent rules whether each instrument binds this firm — quoting the clause that decides, including for the No.
ExtractEach obligation is drafted grounded to its source: circular, paragraph, and the exact character span of the clause.
VerifyFive deterministic checks in plain code — citations resolve verbatim, deadlines parse, applicability matches, schema validates, chain appends. Any failure stops the run.
Human gateDrafts hold at pending-review. A named compliance officer approves or rejects; nothing reaches the register any other way — enforced structurally, the drafting path cannot write to it.
Amend / diffOn amendment the engine diffs old against new and re-maps only what changed; untouched obligations are never re-reviewed.
AuditEvery action appends to a SHA-256 hash chain. Integrity is verified by recomputation from content, so alteration of any record is detected by arithmetic.

Agents are ephemeral workers inside the pipeline; the typed obligation ontology is the permanent artefact. This is the only agent architecture a regulator can audit: every step recorded, every judgement replayable, every write signed.

Live execution layer — /live, in production now

The pipeline executes. These results are observed, not claimed.

Chain integrity — recomputed

Every audit event is SHA-256 hashed over its content plus the previous hash. Verification recomputes from content: the in-product tamper test edits one stored record, and verification then fails at that exact index — stored c275c5cefec9 ≠ recomputed 898698aa53d8. Independently re-derived outside the product: 61 events, 0 mismatches.

Verifier — rejects fabrication

Citations resolve by exact string match against the submitted clause; character offsets are derived from the match. A fabricated excerpt fails and the run stops. So does a one-word paraphrase — which is how hallucination actually presents. Nothing failing a check can reach the register.

Authorisation gate — persisted

Approve and Reject mutate state in the session store. An approved obligation enters the register as gap — approved, no evidence bound yet — never as met. A second decision on the same draft returns 409. The drafting path has no write access to the register.

Extraction — live model call

One serialised LLM call per run, grounded to computed offsets. Observed latency 11s–500s+ on free-tier capacity; a run orphaned by the edge runtime is settled at read time as an honest failure rather than left spinning. No fabricated results on timeout, ever.

Per-visitor sandboxes (session-keyed store), seeded from the same data — one reviewer's approvals never leak into another's view. The seeded register, evidence artifacts and tasks elsewhere in the sandbox remain simulated and labelled as such.

Inspection surface — RegTech and SupTech on one graph

One obligation graph, two windows.

Broker console

The compliance team's working surface: register, evidence vault, document vault, remediation queue, pipeline runs. Gaps become tasks with owners and the circular's own deadlines. The officer stops reading PDFs and clears a queue.

Inspector view · read-only

The same data under a regulator's lens — enforced read-only by the interface. Any control traces to its clause, its evidence, and its tamper-evident history in three clicks; what once needed a data room and a week of correspondence becomes navigation.

MCP surface — machine-queryable compliance

The register is also a protocol: seven read-only tools over the ontology, with an inspector-scoped token in place of a data-room export. A regulator's own agent asks "is this firm compliant with the CUSPA circular?" and receives an answer traceable to clauses — and the inspector's queries are themselves appended to the audit chain. Because the ontology is open, every firm publishing it becomes comparable: the same question returns comparable answers, which is PS2's divergent-interpretation pain addressed at the root.

Market & model

A forced-purchase market, under-served at the small end.

Who pays

India's thousands of small and mid-size stock brokers, RIAs and portfolio managers — bound by the same rulebook as the largest firms, priced out of Big-4 compliance. Compliance spend is non-discretionary and deadline-driven.

Model — open core

The obligation ontology is open: it sets the standard and makes compliance comparable across firms. The engine, evidence connectors and audit vault are the paid per-intermediary subscription, priced an order of magnitude below manual compliance.

Expansion

The engine is corpus-driven: the same pipeline points at the LODR, RA/IA and PMS rulebooks with no structural change — then at other Indian regulators. Each new corpus is an ingestion job, not a rebuild.

Alignment with the mandate: stronger compliance at thousands of small intermediaries is investor protection delivered through infrastructure. A shared open ontology also gives the regulator something it cannot buy today — the same question, answered comparably, across every firm that publishes it.
